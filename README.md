# KU Bridge — React (v3 요구사항 대응 독립 재구현 v2)

> **중요:** 이 프로젝트는 이전 ChatGPT Sites에 배포했던 KU Bridge v3의 **원본 저장소를 추출한 것이 아닙니다.** 확인된 v3 기능 요구사항을 기준으로 별도 작성한 React 구현입니다. 이전 사이트의 픽셀 단위 디자인이나 원본 코드의 동일성은 검증할 수 없습니다. 기존 라이브 사이트는 변경되지 않았습니다.

건국대학교 **서울캠퍼스** 외국인 유학생들이 학교 제도와 행정 절차를 쉽게 발견하고 학교 공식 안내까지 이동할 수 있도록 만든 독립형 탐색 서비스입니다. 건국대학교가 운영하는 공식 사이트가 아닙니다.

## 실행하기

요구 환경: Node.js 20 이상, 인터넷 연결(npm 패키지 최초 설치 시 필요)

```bash
npm ci
npm run dev
```

브라우저에서 Vite가 출력한 로컬 URL(보통 `http://localhost:5173`)을 열어 사용합니다.

## 현재 FE 구성과 수정 사항

React 18 + Vite 기반 단일 페이지 앱이며 별도 서버 API 없이 동작합니다. `src/data.js`와 `src/details.js`에서 45개 안내를, `src/i18n.js`에서 네 언어의 문구를 관리합니다. 문의처와 문의 문안은 `src/routing.js`, URL 이동은 `src/navigation.js`, 브라우저 저장은 `src/services/personalData.js`와 `src/storage.js`에서 처리합니다.

화면은 OS 테마와 관계없이 화이트 모드로 고정했습니다. 네온 색상, 그라데이션, 떠 있는 장식 카드, 숫자 강조를 제거하고 검색·분야별 안내·문의처·체크리스트를 중심으로 재구성했습니다. 저장 화면에 남던 다른 화면의 필터와 잘못된 저장 데이터로 인한 오류를 수정하고, 상세 창의 키보드 포커스와 복사 실패 안내를 보완했습니다.

현재 결과물은 `dist/`의 정적 파일로 배포할 수 있습니다. Firebase SDK·데이터 모델·DB 규칙·Emulator 검증은 준비했지만 외부 계정·실제 DB 연결과 회원·커뮤니티 UI는 아직 추가하지 않았습니다. 기존 안내와 브라우저 저장은 Firebase 설정 없이 동작합니다. 외부 서비스 설정 절차는 [2단계 설정 안내](docs/STAGE_2_SETUP.md)를 확인하세요.

검증 범위와 실행 결과는 [VALIDATION.md](VALIDATION.md)를 확인하세요.

PC·모바일에는 화면 진입·스크롤 등장, 버튼·저장·체크 피드백, 메뉴와 상세 창 전환을 적용했습니다. 추가 애니메이션 라이브러리는 사용하지 않으며, OS의 동작 줄이기 설정을 반영합니다. 스크롤 효과를 지원하지 않는 환경에서도 콘텐츠는 표시됩니다.

프로덕션 정적 빌드:

```bash
npm run build
npm run preview
```

배포는 생성된 `dist/` 디렉터리를 정적 웹 호스팅 서비스에 올리면 됩니다. Node.js 기반 서버나 데이터베이스는 필수가 아닙니다.

콘텐츠 및 React 상호작용 테스트(`npm ci` 후 실행):

```bash
npm test
```

## 1단계: FE 구조 정리

페이지와 공통 UI를 분리하고 페이지별 지연 로딩, 로딩·빈 결과·404·오류 복구 화면을 구성했습니다. 인증 모듈은 현재 `unconfigured` 상태이며 실제 로그인이나 DB 연결을 가장하지 않습니다. 현재 개인 기록은 이전과 동일한 localStorage 키를 사용합니다.

| 화면 | 경로 | 주소에 보관하는 선택 |
| --- | --- | --- |
| 홈 | `/` | 상세 창 `detail` |
| 학교생활 안내 | `/guide` | 검색 `q`, 학생 유형 `student`, 분야 `category`, 상황 추천 `issue`, 상세 창 `detail` |
| 문의처 | `/contacts` | 학생 유형 `student`, 문의 주제 `topic` |
| 개인 체크리스트 | `/my/checklist` | 학생 유형 `student` |
| 저장 항목 | `/my/saved` | 검색·학생 유형·분야·상세 창 |

메뉴는 실제 링크여서 새 탭 열기와 주소 복사가 가능합니다. 검색·선택 변경은 현재 주소를 갱신하고 화면 간 이동은 방문 기록을 추가하므로 뒤로·앞으로 이동과 새로고침에서 선택을 복원합니다. 예: `/guide?student=g&category=funding`, `/contacts?student=l&topic=askClasses`.

이 단계에서 사용자가 반드시 해야 하는 수동 작업은 없습니다. 확인하려면 로컬 서버가 실행된 상태에서 위 주소를 열고 새로고침·뒤로 가기를 사용할 수 있습니다. 서버를 다시 시작할 경우 프로젝트 폴더에서 `npm ci` 후 `npm run dev`를 실행하고 표시된 주소를 엽니다. 프로덕션 로컬 미리보기는 `npm run build` 후 `node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 5183 --strictPort`로 실행합니다. 이미 5183 서버가 실행 중이면 추가로 실행할 필요가 없습니다.

Firebase·Cloudflare 계정 준비는 다음 2단계에서 진행합니다. 배포할 정적 호스팅은 SPA 경로를 `index.html`로 제공해야 합니다. 공개 서비스 설정과 배포 검증은 2·3단계의 작업입니다.

## 2단계: Firebase 설정·권한 규칙 준비

사용자가 수행할 계정·프로젝트 설정은 [STAGE_2_SETUP.md](docs/STAGE_2_SETUP.md), 데이터 모델과 현재 잠긴 기능은 [SCHEMA.md](firebase/SCHEMA.md)에 정리했습니다. 실제 외부 프로젝트 연결·배포는 아직 수행하지 않았습니다.

```bash
npm run firebase:check
npm run test:rules
```

규칙 테스트는 Java 21·Node 22.12.0에서 확인했습니다. 첫 실행은 Emulator 파일을 내려받고 이후 `.cache/firebase/emulators`를 재사용합니다. 실제 프로젝트 ID를 쓰지 않고 루프백의 `demo-ku-bridge`에서만 실행합니다. 본인 개인 데이터의 제한적 접근을 허용하며 게시판·채팅·관리자 권한 변경은 후속 기능 단계까지 차단합니다.

`.env.example`을 `.env.local`로 복사하고 실제 웹 앱의 공개 설정을 입력하면 `firebase:check`에서 형식을 확인할 수 있습니다. 관리자 비밀을 `VITE_*`에 넣지 않습니다. `npm run build`는 프로덕션 설정 검사를 포함하며, 완전 미설정은 허용하지만 일부만 입력한 설정·잘못된 값·프로덕션 Emulator 모드는 거부합니다.

실제 프로젝트 규칙 배포는 `npm run firebase:deploy-rules -- 실제프로젝트ID`로만 수행하도록 대상을 명시합니다. 로컬 테스트 통과는 실제 규칙 배포나 회원 기능 출시를 뜻하지 않습니다.

### 45개 항목의 성격

모든 항목이 현재 신청 가능한 **혜택 45건**을 뜻하지 않습니다. 입학 전부터 졸업까지 관련 제도, 학교 행정 절차, 교류 프로그램, 공식 안내 경로를 통틀어 **45개 탐색 주제**로 구성했습니다. 일부 자료는 과거 학기 모집 공지입니다.

금액, 지급요건, 신청 기간, 학번별 졸업요건과 담당 부서의 최종 책임은 반드시 학교 공식 페이지에서 확인하세요. 4개 언어 안내문은 **독립 프로젝트의 참고 번역**이며 건국대학교의 공식 번역이나 법적 판단이 아닙니다.

## 관리 및 운영 유의사항

- 운영 환경에서 실시간 공지 자동 수집, 사용자 로그인, 신청 대행, 민원 접수, 행정 부서 이관은 지원하지 않습니다.
- 체크리스트는 개인 기록 기능이며 대학의 졸업사정 결과와 무관합니다.
- React 프로젝트를 수정하여 재배포하더라도 이전 Sites v3 사이트가 자동으로 업데이트되지는 않습니다.
- 학교의 최신 자격·일정·정책은 이용자가 해당 공식 출처에서 직접 확인합니다. 운영자는 학사·행정 업무를 접수·대행하거나 공식 판단을 제공하지 않습니다.
- 유학생 대상 인터뷰는 1건이며 전체 유학생에 대한 일반화 근거로 사용하지 않습니다.
